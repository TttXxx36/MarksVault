# 使用 GitHub 备份 schema v2 和统一恢复流程

状态：accepted。

MarksVault 的新 GitHub 书签备份使用包含语义根目录、节点类型、路径指纹、数量、深度和内容哈希的 schema v2。旧版 `version: '1.0'` 文件仍可读取，但只会先迁移为本地“导入”快照，再进入统一的差异预览、恢复计划和逐项恢复日志流程。新上传不会改写旧文件，读取时优先选择最新有效 v2，找不到时回退到 v1。

未知浏览器根目录进入本次恢复专用的 `MarksVault Imported - <时间>` 文件夹；该文件夹 ID 写入恢复日志，重复继续执行时复用。separator 在目标浏览器支持时保留，不支持时记录 warning；unmodifiable 节点永不写入。

GitHub API 错误统一分为认证、权限、限流、网络、服务端、冲突和校验类别。只对 429/5xx 和网络层临时错误进行有限重试，并解析 `Retry-After`、剩余配额和重置时间；不对凭据错误、权限错误或 schema 冲突自动重试。

考虑过的方案：继续使用直接覆盖书签栏的 v1 恢复、同时上传两份 schema、把未知根目录强行映射到书签栏、对所有错误统一重试。它们会造成旧备份结构丢失、重复写入、误放根目录或在凭据错误时扩大副作用，因此选择 v2 单写、v1 兼容读取和统一的选择性恢复流程。
