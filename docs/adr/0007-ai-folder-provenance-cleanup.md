# AI 分类前快照的来源约束文件夹清理

状态：accepted。

## 背景

AI 分类确认执行时会按分类创建文件夹。恢复“AI 分类前”快照时，书签可以安全地移动回原位置，但如果直接按名称或按“空文件夹”删除，可能误删用户在快照之后创建或修改的文件夹。另一方面，完全不处理 AI 创建的空文件夹会留下恢复前不存在的目录，破坏用户对恢复结果的预期。

## 决策

AI 分类计划持久化记录本次实际创建的文件夹 ID，以及创建时的父目录 ID和名称。恢复与该计划匹配的 `ai-classification-before` 快照时，将这些 ID 写入恢复计划和恢复日志，并在书签恢复操作完成后逐项重新检查：

1. 文件夹仍然存在、类型仍为文件夹且未受保护；
2. 文件夹仍为空；
3. 父目录和名称与创建时记录一致。

只有同时满足上述条件的文件夹才会删除。删除成功或跳过都会写入 journal；检查或删除过程发生异常时，任务标记为“结果不确定”，不自动重试。普通快照之后新增的文件夹、被用户移动或重命名的 AI 文件夹，以及包含用户新增内容的文件夹，全部保留。

AI 分类自身的回滚采用同一份来源元数据保护，避免用户在分类完成后移动或重命名空文件夹时被撤销操作删除。

## 后果

恢复结果可以回到分类前的目录结构，同时不会用标题猜测归属或静默删除用户内容。旧版没有来源元数据的 AI 计划不会触发文件夹清理，只能通过普通恢复差异保守地跳过这些新增目录；升级后新生成的计划具备完整保护信息。
